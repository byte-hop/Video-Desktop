================================================================================
0. 一句话定位
================================================================================

把安卓 TVBox 的「配置订阅 + 多站点聚合搜索 + 多线路选集播放」这套能力搬到
Windows 电脑上，界面走纯白极简路线，但利用电脑宽屏优势把内容密度做高：
一屏能看到足够多的海报、剧集和搜索结果，鼠标操作优先，键鼠快捷键齐备。

三条硬边界，写在代码里而不是口号里：

  1) 软件不含任何影视内容。仓库里没有采集接口、没有直播源、没有推荐订阅，
     presets.ts 的 SOURCE_PRESETS 是空数组，ensureBundledSources() 恒 false。
  2) 不做破解。不内置解析接口、不带 cookie、不绕会员鉴权，解析接口由用户自己
     在设置页添加。
  3) 便携。配置、缓存、下载、历史全部落在程序同级的 data\，不写
     %APPDATA%，删目录即彻底干净。

1. 技术选型
================================================================================

外壳        Electron 44            跨平台桌面外壳，Windows 免额外工具链
构建        electron-vite 5        主进程 / preload / 渲染进程三端统一构建
界面        React 19 + TS 7        组件化 + 类型安全
样式        原生 CSS + CSS 变量     不引入 UI 框架，纯白设计体系完全自控
状态        Zustand 5              轻量全局状态（源、搜索、播放、UI）
路由        react-router-dom 7     HashRouter（桌面端避免 file:// 路由问题）
播放        ArtPlayer 5            播放器内核，控制条完全自定义
流媒体      hls.js 1.7             m3u8 / HLS 播放，兼容绝大多数采集站
HTML 解析   cheerio 1.2            type=1 网页规则站抓取
编码        iconv-lite 0.7         GBK / GB2312 直播源与网页转码
本地存储    JSON 文件              放 data\ 目录，避免原生模块重编译
打包        electron-builder 26    NSIS 安装包 + 免安装 zip

设计原则

  1) 主进程负责一切网络请求与文件读写，渲染进程只管展示。
     既安全（渲染进程拿不到 Node），又能绕过 CORS 与防盗链。
  2) 不引入需要 node-gyp 编译的原生依赖，clone 下来 npm i 就能跑。
  3) 界面只用系统字体（思源黑体 / 微软雅黑 fallback），不加载网络字体。
  4) 所有「看起来会失败」的地方都要写出失败原因，不假装成功。

2. 运行架构
================================================================================

  ┌────────────────────────────────────────────────────────────────────┐
  │ 渲染进程（React，无 Node 权限）                                    │
  │  pages/ 10 个路由页 · components/ 18 个 · store/useApp.ts          │
  └───────────────▲───────────────────────────┬────────────────────────┘
                  │ window.api（contextBridge，白名单方法）            │
                  ▼                           ▼
  ┌────────────────────────────────────────────────────────────────────┐
  │ 主进程                                                             │
  │  index.ts   窗口 / 生命周期 / IPC 注册 / 托盘 / 启动预热 / 静默自检│
  │  services/  30 个领域服务（网络、解析、播放、下载、缓存、更新）    │
  │  store.ts   统一 JSON 落盘（内存缓存 + 防抖 + 临时文件改名）       │
  └────────────────────────────────────────────────────────────────────┘

预加载层只做一件事：把 src/shared/ipc.ts 里的通道名映射成
window.api.xxx.yyy(...) 的函数，订阅型接口（如 update.onAvailable）返回
取消订阅函数，渲染进程不直接碰 ipcRenderer。

主进程窗口参数要点：

  - frame: false，自绘标题栏，最小化 / 最大化 / 关闭三键在顶栏右侧。
  - 关闭默认收进托盘（见「下载 · 托盘驻留」），真退出走托盘菜单「退出影视窗」，
    或 app:quit 通道（forceQuit 后 app.quit()）。
  - 建窗前先做系统代理探测（proxy.ts），避免 Chromium 抓到已死的代理链。
  - 建窗后 6 秒起一次静默版本自检（update.ts），只有真的更新才发
    app:update-available。

IPC 通道分区（src/shared/ipc.ts）

  app:*          窗口控制、外部链接、退出、声明状态、更新可用通知
  sources:*      配置源的增删改查与同步
  sites:*        影视源汇总、覆盖、启用、连通性测试
  custom:*       手动站点 / 手动直播频道 / 手动解析接口
  search:*       聚合搜索（含流式进度与取消）
  category:*     分类树、分类列表、翻页、预取
  detail:*       详情与选集
  live:*         直播分组、频道、体检、房间号换地址
  player:*       外部播放器探测与唤起
  library:*      收藏与历史
  download:*     下载任务队列与控制
  ai:*           剧情总结（文字 / 抽帧）
  settings:*     设置读写（含海报缓存上限即时清理）
  update:*       版本检测

约定：主进程 handler 一律返回可序列化结构；异常统一包成
{ ok:false, message } 或直接 throw，渲染进程负责翻译成人话。

4. 数据模型
================================================================================

Site（一个可搜索的站点）

  key         唯一键，配置里同名会加后缀去重
  name        中文名
  type        归一化后的类型：cms / html / api / spider / unknown
  api         基地址或带 {ac}{wd}{pg}{t}{ids} 占位符的模板
  searchable  是否参与聚合搜索（默认 1）
  quickSearch 是否参与快速搜索
  filterable  是否有分类筛选
  categories  站点自带分类（可选）
  header      站点级请求头（可选）
  timeout     站点级超时（可选）
  enabled     是否启用（本地覆盖，落 sites.json）

Vod（搜索结果 / 列表项）

  siteKey siteName vodId vodName vodPic vodRemarks vodYear vodArea
  vodClass typeId  评分 rating  以及原始条目 raw

VodDetail（详情）

  vod           基础 Vod
  content       简介
  lines[]       线路数组，每条含 episodes[]（名称 + 地址）
  sourceGroup[] 同名影片的其它站点条目（换源用）

AppSettings（全局设置，落 settings.json）

  searchConcurrency  1–32，默认 3            同时请求的站点数
  requestTimeout     秒，默认 30             单站点搜索/详情最长等待
  hideCommentary     默认 true               搜索过滤解说 / 速看 / 混剪
  userAgent          默认 Chrome 126 UA       部分站点校验 UA
  externalPlayer     空 = 自动探测            外部播放器完整路径
  playerArgs         默认 {url}               参数模板，{url} 代表地址
  posterCacheMb      200 / 300 / 400 / 500    海报缓存上限
  apiKey             DeepSeek Key，只存本机
  language           zh / en                 外壳语言
  skin               11 套之一               皮肤
  accent             强调色                  顶栏 / 按钮 / 开关 / 进度条

UpdateCheckResult

  status  latest | newer | ahead | error
  current latest url message

5. 配置源与 JSON 方言
================================================================================

两种方言都吃，扩展字段统一放在 tvboxDesktop 键下，对安卓 TVBox 无副作用。

A 方言：直接填现成的 TVBox 订阅地址，sites / lives / parses 原样解析。

B 方言（手写推荐）：

  {
    "format": "tvbox-desktop/1",
    "name": "我的订阅",
    "sites": [
      { "key": "example_cms", "name": "示例站", "type": "cms",
        "api": "https://example.com/api.php/provide/vod", "searchable": 1 }
    ],
    "lives":  [ { "name": "直播源", "url": "https://example.com/live.txt" } ],
    "parses": [ { "name": "解析", "type": 1, "url": "https://example.com/jx?url=" } ],
    "headers":[ { "host": "*.example.com",
                  "header": { "User-Agent": "okhttp/3.12.0" } } ],
    "tvboxDesktop": {
      "home": { "sections": [
        { "title": "电影 · 最近更新", "site": "example_cms" },
        { "title": "电影 · 动作片", "site": "示例站", "typeId": 6 } ] }
    }
  }

站点 type 映射（数字与字符串都认）

  3 / "cms"      苹果CMS（主力）   搜索 OK  分类 OK   api 可写基地址或模板
  1 / "html"     网页规则站        搜索 OK  分类 NO   靠 rules 里的选择器抓
  4 / "api"      CMS 变体          搜索 OK  分类 OK
  0 / "spider"   需要 jar/dex      灰显并说明「桌面端跑不了」
  2 / 其它       未知类型          灰显并标「未知」，不降级冒充 CMS

归一化规则（config.ts）

  - type 先按数字查表，字符串再去空格小写查表，都不中就 unknown。
  - sites 里缺 key 时用 name 生成，重复 key 自动加 -2 -3 后缀。
  - api 里的 {ac}{wd}{pg}{t}{ids} 占位符保持原样，交给 cms.ts 按存在与否分别替换；
    没有 {ids} 槽位的模板在替换完之后按现有分隔符补上 ids（否则详情永远解析不出剧集）。
  - headers 的 host 通配（*.example.com）在 http.ts 里统一匹配，站点级 header
    优先级高于全局。
  - 未知字段原样保留在 raw，不丢用户数据。

同步行为（sources.ts）

  - 同步 = 请求订阅地址 → 归一化 → 合并进源列表；同 address 的源原地更新，
    不同 address 新增；删除只影响本地列表，不动远端。
  - 启动时对已启用源做一次回填：sites.json 里的本地覆盖（enabled / 排序）
    重新套到新拉的站点上。
  - 一个源同步失败不影响其它源，错误挂在那个源自己身上（页面能看到原因）。

内置订阅

  presets.ts 的 SOURCE_PRESETS = []，addPreset() 直接抛「这个版本不带内置订阅」，
  ensureBundledSources() 恒 false。首启页 / 设置页的「一键添加内置订阅」区块按
  数据渲染，数组为空就整块不显示，界面不用改。


================================================================================
6. 网络层（http.ts）
================================================================================

一切出站请求都走这里，不允许各服务自己 fetch。要点：

  1) UA：默认一段 Chrome 126 的 UA，设置页可改；站点级 header 里的 UA 覆盖全局。
  2) 超时：默认 30 秒，可全局改；站点级 timeout 覆盖；AbortController 真中断。
  3) 编码：响应头不是 UTF-8 时用 iconv-lite 按 GBK/GB18030 解码；先探测
     charset 再降级，不猜错就把乱码丢给用户。
  4) header 通配：按 host 模式（*.example.com）匹配后附加，直播体检也会带上，
     因为不少直播网关校验 Referer/UA。
  5) 重试：连接层错误（DNS / TCP / TLS）重试 2 次，指数退避；HTTP 4xx/5xx
     不重试（那是对方态度，重试只会更糟）。
  6) 代理：Node 的 fetch 不读系统代理。启动时 proxy.ts 用 resolveProxy 问出
     代理链，对每个 host:port 做一次 800ms TCP 探测，只要有一个在监听就照旧
     走系统代理，一个都连不上才把这次会话切到 direct:// 并打 [proxy] 警告。
     每次启动只判断一次。
  7) 日志只记方法、主机、状态码、耗时，不记完整地址里的 token。


================================================================================
7. 首页
================================================================================

首页上下两段，数据源两套：

一、网络精选池

  - 轮播 7 部：电影 / 剧集混排，左边简介右边竖版海报，底部圆点可切，
    5 秒自动翻页；片名、年份、地区、类型来自网络榜单，简介截断三行。
  - 四条精选：电影 / 剧集 / 综艺 / 动漫，卡片角上是评分，横向滚轮或箭头翻，
    右上角「更多」跳分类页。
  - 抓取节奏：周键按周一算，一周一抓；结果落 data\ 下的精选快照，一周一份。
    本周没抓过就先用旧缓存画，后台再更新——首屏不等网络。
  - 海报单独缓存到 data\ 下的精选海报目录，避免反复打图床。
  - 不再写「热门」角标：精选池条目的 vod_remarks 置空，
    utils/remarks.ts 的 RETIRED_TAGS 兜住旧缓存里的同名字样，HomeRail /
    VodCard / HeroCarousel / Detail 四处统一走 displayRemarks()。

二、订阅源内容位（home.ts）

  配置里写 tvboxDesktop.home.sections 就按配置画，没配就每个可用源一条
  「最近更新」，行尾打「自动」标签。

  - site 既可以是站点 key，也可以是中文名：
    key 精确 → 中文名精确 → 忽略大小写 → 互相包含。
  - 给了 typeId 就是「分类推荐」，不给就是该源的「最近更新」。
  - 一行拉不到不影响别人：写错的源只让那一行显示一行错误文字。
  - 结果在主进程缓存 10 分钟，失败的只缓存 1 分钟；hero 上的「刷新内容位」
    是强制重拉。
  - 每行最多 24 条，没有「换一批」（见「已知限制」）。


================================================================================
8. 搜索
================================================================================

顶部搜索框回车即聚合搜索，是整条链路的第一环。

并发与流式

  - 并发池按站点并发，并发数取 settings.searchConcurrency（1–32，默认 3）。
    太高会被部分站点限流，页面上有这句提示。
  - 每条站点的结果一到就往渲染进程推（IPC 事件），首屏不必等最慢的源；
    搜索中可随时取消，取消会 abort 所有在飞的请求。
  - 单站点超时取 settings.requestTimeout（默认 30 秒）。

合并与去重

  - 同名影片跨站合并成一张卡，标「N 个源」，鼠标悬停列出具体站点。
    mergeResults() 按归一化片名归组，组内按信息量排序取主条目。
  - 一个站点只留一条：同一站对同一部剧返回多条时，按
    「有海报 > 有备注 > 有评分，同分取名字短的」保留信息量最大的一条。
  - 别名括号会去掉：`庆余年，全世界都以为我是废物太子（庆余年之大凉太子爷）`
    与不带括号的合成一条；但括号里是分季分集信息（`第61-81集`、`特别篇`）
    时保留。
  - 片名归一化（utils/normalize.ts）：NFKC → 小写 → 去空白与标点。刻意保守，
    不剥「第二季」「(国语)」这类后缀——宁可漏合，不误合。

解说过滤

  - 开关在设置页（hideCommentary，默认开）。
  - 判定两条线索：片名关键词（[电影解说] / 一口气看完 / 速看 / 混剪），
    或者分类字段（vod_class / type_name）是「影视解说」。
  - 挡掉的条数写在搜索页副标题里，不做静默丢弃。
  - 只作用于聚合搜索，不影响分类浏览。


================================================================================
9. 分类浏览（/search 的目录模式）
================================================================================

侧栏第二项「影视分类」进的是同一个页面，只是切成目录模式。**没有搜索框**——
找片名用顶部全局搜索，这一页是「不知道看什么」时用的。

数据获取

  - 打开时向每个可搜索的 CMS 站点拉一次 ac=list，拿各自分类树。
  - 归并成统一大类：电影 / 电视剧 / 动漫 / 综艺 / 纪录片 / 短剧 / 体育 / 少儿。
  - 点进大类后上方出现子分类标签，标签上的数字是覆盖到几个站点。
  - 分类结果缓存 10 分钟（class-cache.json / category-index.json）。

归并对**整条祖先链**做，不是只看顶层：

  记录片   挂在「电影片」下面，且写的是「记录」不是「纪录」
           —— 漏了这个字就会留在电影里；
  短剧     挂在「连续剧」下面，要拆出来；
  动画片   挂「动漫片」下归动漫，挂「电影片」下归 电影 → 动画；
  伦理片   部分站是子分类，SKIP 规则沿祖先链生效，命中就整棵子树丢掉。

尺度过滤只按分类名挡，且只在分类浏览里生效。

翻页

  - 滚到底自动加载下一页（IntersectionObserver 提前 500px）。
  - 首屏一画完就在后台预取下一页，滚到底直接换上。
  - **已上屏的卡片不会被重排**：mergeResults() 收一个 previousOrder，
    排完序把出现过的按原名次放回，新出现的接在后面。翻页时视觉稳定，
    不会「跳一下」。

11. 播放链路
================================================================================

内嵌播放器

  - ArtPlayer + hls.js：倍速、进度条、全屏、画中画齐全。
  - MSE 走 blob:，所以抽帧与同源读取不会触发跨域防护。
  - 起播直接选最高档（hls.nextLevel，不是会把 ABR 钉死的 currentLevel），
    之后仍允许 ABR 降档。
  - 浏览器放不了的格式，点「外部播放器」唤起本机 PotPlayer / mpv / VLC。
  - 播放地址是个可点的小方框：点了用系统默认浏览器打开，右边可复制。

切页不断播（MiniDock，utils/pipDock.ts）

  - 切到别的页面时，正在播的视频缩进右下角小窗继续放，点「回到播放页」
    按上次进度接着看。
  - 开着系统画中画时关窗，视频继续播放，画面留在桌面上；没开画中画时关窗
    先暂停。这样「关窗」不会莫名其妙切掉用户正在看的东西。

换源

  - 播放页侧栏顶部「片源」区块列出各站点条目，点一下换过去继续看。
  - 没走过搜索时点「找其它片源」按片名现搜一次。
  - 点历史时原源连不上会自动换源，带上集数与进度（见第 16 节）。

外部播放器（player.ts）

  - 扫 PotPlayer / mpv / VLC / MPC-HC / MPC-BE / KMPlayer / SMPlayer 的常见
    安装路径（含 PATH），还会问注册表里 .mkv / .mp4 / .ts / .flv 的默认打开方式。
  - 设置页「检测本机播放器」每条结果带「用这个」，点一下填进输入框；
    已生效的标「已选」。
  - 参数模板里 {url} 是播放地址、{title} 是片名，多个参数空格分隔，
    例如 `--fullscreen {url}`。


================================================================================
12. 解析接口（parse.ts）
================================================================================

采集站的线路经常给的不是直链，而是分享页地址。丢给播放器只会黑屏，所以三步：

  1) 本来就是直链就直接放。只看协议与扩展名
     （m3u8 / mp4 / flv / mkv / ts / mpd…），不做域名白名单——
     CDN 域名天天换，白名单只会误伤自己。
  2) 先自己读一遍那个页面。十有八九是个 DPlayer 壳，地址明文写在
     `const vid = '…/index.m3u8'` 里，正则抓出来就完事。
  3) 读不出来才按排行问解析接口。

排行打分（同档内比较，越用越准）

  - 分档：声明了匹配线路的优先 → 通配 → 声明了别的线路的。
  - 同档内按成功率（拉普拉斯平滑，避免 1/1 打赢 20/25）+ 平均耗时排序。
  - 失败的会沉下去；连续失败不删除，只降权。

接口来源只有两种：

  配置里带的   订阅 JSON 的 parses 数组，同步后自动出现，不可单独删除
  手动添加     设置页「解析接口」区块，落 data\parses.json，可删

**没有内置任何第三方公开解析接口。**

type=0（需要浏览器嗅探）会打警示标签：它靠前端 JS 算地址，HTTP 拿不到，
目前只支持 type=1/2。换地址失败时播放器会写出**每一条路子分别为什么失败**。


================================================================================
13. 电视直播（live.ts / liveHealth.ts / streamResolve.ts）
================================================================================

源格式

  - m3u：`#EXTINF:-1 group-title="央视",CCTV-1` + 下一行地址。
  - txt：`分组,#genre#` 之后每行 `频道名,地址`。
  - 两套语法解析成同一结构：group → channels[] → lines[]。
  - 同一频道的多个来源合并成一张卡、一条卡上多条线路；卡上标 `2/2 线`。
  - 分组名去掉装饰（「频道」「直播」「IPV4」这类后缀与括号）。

真正的痛点不是源少，是死链多，所以做法是「把已有的线路用起来」：

体检策略（liveHealth.ts）

  - 进分组后后台预热：当前分组前 60 条可探地址交给主进程，
    每次最多 8 条并发，**只读到 4 KB 就断开**（直播流不会结束，
    绝不能整条拉完），顺带从 m3u8 头里记下最高一档画质。
  - 成功缓存 30 分钟，失败只缓存 5 分钟——失败要快速重试，成功不必反复打。
  - 点开频道优先用探到的线路；播放中途失败自动换下一条，并提示
    「这条线路拉不起来，已自动换到第 N / M 条」。
  - 整组都探不到的频道默认藏起来，顶部给「显示 N 个不可用」开关；
    不可用卡打虚线写「不可用」。
  - 右上角「体检线路」= 清空体检表重测一遍；请求会带配置里的请求头。
  - 结果落 data\live-health.json。

房间号频道（streamResolve.ts）

  虎牙、抖音这类平台地址带防盗链签名、几小时失效，所以源里只写房间号：

    游戏赛事,#genre#
    danking直播,huya://10188

  只有点开这个频道时才走一次 IPC 去平台换真地址，换好了才构造播放器。
  没开播时播放区显示「换不到播放地址」+ 原因 + 重试，而不是黑屏。
  换地址在主进程做，页面里不直接请求，避免把签名参数暴露给页面。

14. 下载（download.ts / downloads.ts）
================================================================================

入口：播放页「下载影视」把当前这一集丢进队列。

队列

  - 最多同时下 2 条，其余排队；失败 / 取消的任务可「重试」接着 .part 续。
  - 任务落 data\downloads.json，每完成一段 / 每 1 MB 刷新一次档案。
  - 下载记录页分「正在下载 / 下载完成」：分段进度、百分比、速度、取消；
    完成后可打开所在文件夹、删除单条或清空。

断点续传

  - 一律先写 `<文件名>.part`，完成才改成正式名。
  - HLS：记已完成分片数与清单指纹。重启后跳过已下分片、在 .part 末尾追加；
    清单变了（换码流 / 直播滚屏）指纹对不上就自动从头下，绝不拼出坏文件。
  - 直链：用 HTTP Range 从 .part 的字节位置继续；服务器不认 Range（回 200）
    就退回从头下。
  - 主动取消会清掉半截文件（用户说要取消，就别留垃圾）。

托盘驻留

  - 有任务时点关闭只隐藏窗口，下载在主进程继续跑。
  - 托盘菜单显示任务数，可跳到「下载记录」；真退出走「退出影视窗」。
  - 完成提醒：响一声 + 系统通知，点通知回主界面；窗口在前台时另弹一条 toast。

16. 收藏与观看历史（library.ts）
================================================================================

  - 历史每条记下看到第几集、看到哪个时间点、以及是哪个源。
  - **同一部剧在多个源上看过只算一条**：读取时按归一化片名归并
    （全角转半角、统一小写、去空格与标点）。
  - 归一化刻意保守：不剥「第二季」「(国语)」这类后缀，宁可漏合，
    不把不同季的进度串到一起。
  - 一条里收着多个源时，行上出现「N 个源」与可点的源标签，
    主记录是最近看过的那条。
  - 进度条只在知道时长时才画，右侧给 `看到 9:23 / 23:07`；
    时长未知时留白，不画 0% 灰线。
  - 删除删的是这部片在所有源上的记录，多源时先确认一次。
  - 历史最多 200 条，落盘为 JSON。
  - **续播**：从历史点进播放页 seek 回上次位置。recordHistory() 在同一集时
    只有拿到真实时长（duration > 0）才允许改写进度——播放器挂载瞬间会写
    一条 {0,0}，不挡住就会把上次进度抹平。
  - **原源连不上自动换源**：按片名到其它已启用源找同一部，带上集数与进度切过去；
    「谁先返回同名结果就用谁」，不等慢源超时。

17. AI 剧情总结（ai.ts）
================================================================================

  - 播放页播放地址下方一块，**点了才请求**，Key 只在主进程里、只存本机
    （settings.json 的 apiKey）。

    「看一遍再总结」  每 20 秒抽一帧、约 70 帧，作为图像发给 deepseek-flash；

19. 版本检测与自检
================================================================================

版本检测（update.ts）

  UPDATE_REPO = 'byte-hop/Film-Window'，公开仓库不需要 token。
  查 https://api.github.com/repos/.../releases/latest，解析顺序：

    tag_name → name（Release 标题）→ body 首行

  版本号正则 `\d+\.\d+\.\d+(?:[-+][0-9A-Za-z.-]+)?`，三个点号分段比较，
  不做字符串比较（0.1.9 < 0.1.10 这条坑踩过）。

  三态文案：

    已是最新    已是最新版本（GitHub 上发布的是 x.y.z）
    发现新版本  发现新版本 x.y.z + 「前往下载」（openExternal 跳 Release 页）
    本机更新    当前 x 比 GitHub 上的 y 新，无需更新
    失败        检测失败 + 原因（连不上 GitHub / 还没发过 Release）

  启动后静默自检：进主界面 6 秒后查一次，只有 status === 'newer' 才
  发 app:update-available，渲染进程弹一条 toast 指路「设置 · 版本」。
  离线、限流、还没发 Release 一律不打扰。

自检（scripts/selftest.mjs）

  起本地桩服务器（苹果CMS + 网页规则站 + 假 m3u8 + 占位海报），
  再用 CDP 驱动真实窗口跑一遍端到端断言，当前 13 块、176 处 check()：

    1) 六个路由渲染            2) 配置解析（A/B 方言）
    3) 站点类型归一化          4) CMS / 网页站连通性（含失败路径）
    5) 自定义请求头透传        6) 搜索 → 详情 → 选集 → 播放全链路
    7) 分类浏览（归并、归位、伦理片整棵丢、翻页稳定）
    8) 电视直播（两种格式、跨源合并、体检、死链开关）
    9) 收藏与历史（跨源合并、行上换源）
   10) AI 总结（位置、「点了才请求」、有无 Key 分支）
   11) 解析接口（直链 / 读页 / 兜底轮询 / 战绩分档）
   12) 首页内容位（命名空间、按 key 与中文名找源、写错的源只报一行）
   13) 页面无 JS 异常

  [9/13] 段要清干净收藏与历史才对得上数目，所以脚本开头备份、末尾还原；
  updatedAt 会被刷新，还原后这些记录显示「刚刚」。
  自检刻意不真调 DeepSeek，只按设置里有没有 Key 分开断言界面。
  滚动加载这类依赖渲染帧的断言要求页面可见且聚焦
  （Page.bringToFront + Emulation.setFocusEmulationEnabled），
  否则 Chromium 会把 rAF 与 IntersectionObserver 完全节流。

20. 系统代理
================================================================================

界面里的海报和视频走 Chromium，主进程的请求走 Node——两者对系统代理的处理
不一样：Chromium 听 Windows 的代理设置，Node 的 fetch 根本不读它。

所以当系统代理开着、代理软件却没在跑时（Clash 内核退了但 ProxyEnable 还留着），
会出现「搜索、详情、分类、直播分组全正常，但界面里所有图片和视频都黑，
控制台一片 ERR_PROXY_CONNECTION_FAILED」。

proxy.ts 在建窗口之前处理：resolveProxy 问出代理链，对每个 host:port 做一次
800ms TCP 探测，只要有一个在监听就照旧走系统代理，一个都连不上才把这次会话
切成 direct:// 并打 [proxy] 警告。每次启动只判断一次。

21. 数据目录
================================================================================

配置、缓存、下载记录都在**程序同级的 data\**，不写 C 盘用户目录：

  开发      <源码目录>\data\
  打包后    <exe 所在目录>\data\

data/
  settings.json     应用设置（含语言、皮肤、海报缓存上限、API Key）← 别外传
  sources.json      配置源
  sites.json        站点本地覆盖（启用 / 排序）
  custom-sites.json 手动添加的站点
  custom-lives.json 手动添加的直播频道
  parses.json       手动添加的解析接口
  downloads.json    下载任务与断点档案
  disclaimer.json   首启声明同意状态
  picks.json        精选池快照（一周一抓，约 230 KB）
  picks-posters/    精选池海报缓存
  poster-cache/     海报图缓存（按上限自动清理）
  home-cache.json   首页内容位快照（10 分钟）
  browse-cache.json 分类浏览快照
  category-index.json / class-cache.json  分类树与归类结果
  live-health.json  直播线路体检结果
  history / favorites  收藏与观看历史（历史最多 200 条）
  session/          Chromium 缓存（会很大，删掉只影响下次启动稍慢）

如果这个位置建不出来（比如装到了只读目录），会自动退回系统默认用户目录并在
控制台提示。

store.ts 的落盘策略：内存缓存读 → 写时防抖 300ms → 写临时文件 → 改名替换。
断电或崩溃最差只丢最后一次未落盘的修改，不会把 JSON 写成半截。

22. 打包与发布
================================================================================

两条发布路径

  A. 安装包：npm run build:win → electron-builder 出 NSIS 安装向导
     （oneClick: false，可改目录、建开始菜单与桌面快捷方式）与免安装 zip，
     产物落 release/。
  B. 便携替换（日常小迭代用）：只重打 resources\app.asar。

便携替换流程（BUILD → PACK → VERIFY）

  1) 改 package.json 的 version，同时把 package-lock.json 三处版本号改成同值。
  2) npm run typecheck、npm run build。
  3) 关掉正在跑的影视窗进程。
  4) 准备 .tmp-asar\app：拷 out\、package.json，装生产依赖。
  5) asar pack 出 app.asar，备份旧的到 resources\backup\app.asar.<时间戳>，
     覆盖 resources\app.asar。
  6) 同步 build\icon.ico，重新启动安装版；确认进程数与 asar 里的版本号。

版本递增规则：补丁位 +1（0.1.29 → 0.1.30 → …），每版必须在 CHANGELOG.md
顶部写一条，写明改了什么、为什么。

发版

  tag 直接写 `v0.1.30` 这种最省事；写成别的（比如 `film-Windows`）只要
  Release 标题里带版本号也能被客户端认出来。
  Release 只挂编译版 zip（`影视窗-<版本>-编译版-无影视源.zip`，约 168 MB），
  不挂源码包——避免别人直接打出带本地配置的包。

应用图标是代码生成的：node scripts/make-icon.mjs 零依赖自编 PNG，
写出 build\icon.png（512×512）与内嵌多尺寸的 icon.ico
（16/24/32/48/64/128/256），造型与界面左上角 logo 一致。

没有代码签名证书，首次运行会触发 SmartScreen 提示（更多信息 → 仍要运行）。
装完即用的「带源」形态在 0.1.23 已取消：这个版本一条内置源都不带。

23. 已知限制
================================================================================

  - 只支持桌面端能跑的站点类型：苹果CMS（type 3/4）与网页规则站（type 1）。
    需要 jar/dex 的 spider（type 0）跑不了，会灰显并写明原因。
  - 解析接口只做 HTTP 解析（type 1/2），type=0 的浏览器嗅探还没做。
  - 首页内容位只按「最近更新」或指定分类拉一页（每行最多 24 条），没有
    「换一批」；配置里只能写 site / typeId。
  - 外部播放器检测是扫路径 + 问注册表，不是遍历全盘；装在奇怪目录的
    播放器得手填一次。
  - 播放进度取决于源：能直接给 m3u8 的源进度是真的，只给分享页地址的源
    拿不到进度；拿不到时长就不画进度条。
  - 语言开关只翻「外壳」，页面正文与使用声明仍是中文。
  - 没有代码签名证书，首次运行会触发 SmartScreen。
  - Windows 上点关闭只会收进托盘，要真退出走托盘菜单「退出影视窗」。
  - 自己添加的采集站随时可能失效，在「影视源」页点「测试」就能看出来。
  - 直播画质只做到「起播选最高档」，没有手动切档 UI。
  - AI 总结没有音频输入，只靠画面与文字资料推断。

附录 B. 术语
================================================================================

  配置源      一个订阅地址或本地 JSON 文件，同步后产出站点 / 直播源 / 解析接口
  站点        一个可搜索的数据源条目（CMS 接口或网页规则站）
  线路        详情页里的一条播放路径（play_url 里 $$$ 分隔的段）
  直链        能直接交给播放器的地址（m3u8 / mp4 / flv / mkv / ts / mpd）
  分享页      DPlayer 之类的外壳页，地址藏在页面 JS 里，需要解析
  房间号频道  huya://10188 这种，播放前才换真地址
  体检        只读 4 KB 判断直播线路是否活着，并记下最高画质
  周键        精选池的抓取周期标识，按周一换一次
